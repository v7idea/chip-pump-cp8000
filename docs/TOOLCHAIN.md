# Toolchain Setup

The CP8000 vendor SDK projects are generated by C-Sky CDK and expect this compiler family:

```text
riscv64-unknown-elf-gcc
riscv64-unknown-elf-g++
riscv64-unknown-elf-ar
riscv64-unknown-elf-objcopy
riscv64-unknown-elf-objdump
riscv64-unknown-elf-size
```

The CDK-generated Makefile inspected from the vendor SDK uses:

```text
ToolchainPath=D:/C-Sky/CDKRepo/Toolchain/XTGccElfNewlib/V3.2.0/R/
-mcpu=e902m
```

## Vendor Download URL

The original SDK bundle includes this tool download URL:

```text
https://www.xrvm.cn/community/download?id=4453983171205206016
```

Probe result on 2026-05-05:

- HTTP status: `200`
- Content type: `text/html;charset=UTF-8`
- Result: returns the XuanTie website HTML shell, not a direct archive.

This means CI cannot currently fetch the toolchain directly from this URL. A release-quality toolchain package still needs one of:

- a direct redistributable archive URL
- a checked license and mirrored Arduino tool package
- manual local installation documented for developers
- vendor-provided command-line installer/download endpoint

## Expected Local Layout

For Arduino CLI development, place or symlink the toolchain here:

```text
arduino/hardware/chippump/cp8000/tools/riscv64-unknown-elf/bin/
```

The following command must exist:

```bash
arduino/hardware/chippump/cp8000/tools/riscv64-unknown-elf/bin/riscv64-unknown-elf-g++
```

This repository includes wrapper scripts in that directory. The wrappers look for a real toolchain through:

```bash
export CP8000_TOOLCHAIN_PATH=/path/to/XTGccElfNewlib/V3.2.0/R
```

or:

```bash
export CDK_TOOLCHAIN_PATH=/path/to/XTGccElfNewlib/V3.2.0/R
```

You can also create symlinks with:

```bash
scripts/link_toolchain.sh /path/to/XTGccElfNewlib/V3.2.0/R
```

## Verified Downloaded Toolchain

The following downloaded toolchain matches the CP8000 bare-metal target:

```text
../SDK/Xuantie-900-gcc-elf-newlib-x86_64-V3.4.0
```

Verification result on 2026-05-05:

- Host binary: Linux x86_64
- Target command: `riscv64-unknown-elf-gcc`
- Version: `Xuantie-900 elf newlib gcc Toolchain V3.4.0 B-20260323`, GCC `14.3.0`
- Required multilib exists: `rv32emc/ilp32e`

The Linux/glibc, Linux/musl, and LLVM Linux packages are not suitable for this bare-metal Arduino SDK.

On Apple Silicon Macs, use Docker with `linux/amd64` platform. The compose file defaults to this platform.

The verified XuanTie package is a Linux x86_64 hosted compiler. Do not expect it
to run directly on macOS. The supported macOS development path is:

1. Keep the toolchain extracted under `../SDK/Xuantie-900-gcc-elf-newlib-x86_64-V3.4.0`.
2. Let Docker run the Linux x86_64 compiler through the `docker-dev/compose.yaml`
   Arduino CLI container.
3. Use `scripts/real_compile_examples.sh` before release work to catch examples
   that compile in fake-toolchain CI but fail with the real compiler.

## Docker Compile Test

After placing the toolchain:

```bash
cd docker-dev
docker compose run --rm arduino-cli \
  arduino-cli compile \
  --config-file /workspace/arduino-cli.yaml \
  --fqbn chippump:cp8000:cp8001_sop16 \
  /workspace/examples/Blink
```

To compile every example with a host-mounted toolchain:

```bash
CP8000_TOOLCHAIN_HOST_PATH=/host/path/to/XTGccElfNewlib/V3.2.0/R \
scripts/real_compile_examples.sh
```

## Recipe Smoke Test Without Toolchain

CI can validate Arduino recipe plumbing without producing real firmware:

```bash
scripts/recipe_smoke_compile.sh
```

This sets `CP8000_FAKE_TOOLCHAIN=1`, which causes the wrapper tools to create placeholder build outputs. This mode only checks Arduino platform integration. It does not compile C/C++ and must never be used for release firmware.

If you are mounting the toolchain into Docker:

```bash
CP8000_TOOLCHAIN_PATH=/opt/cp8000-toolchain \
docker compose -f docker-dev/compose.yaml run --rm \
  -v /host/path/to/XTGccElfNewlib/V3.2.0/R:/opt/cp8000-toolchain:ro \
  arduino-cli \
  arduino-cli compile \
  --config-file /workspace/arduino-cli.yaml \
  --fqbn chippump:cp8000:cp8001_sop16 \
  /workspace/examples/Blink
```

## Distribution Question

Before public Boards Manager release, confirm whether the C-Sky/CDK E902M toolchain can be redistributed. If it cannot be redistributed, the package index must either:

- depend on a separately installable public tool package, or
- document a manual local installation path, or
- use a clean-room compatible public E902M-capable RISC-V toolchain if verified against the vendor libraries.
